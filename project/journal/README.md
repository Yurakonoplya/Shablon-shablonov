# Журнал проекта

Человекочитаемая история: **что решили, что сделали и почему**. Здесь виден путь, которым шёл проект, и особенно нужен он при разборе поломки: с какого момента поведение изменилось.

Журнал растёт всю жизнь проекта, поэтому **разбит на тома**. Этот файл оглавление: по нему видно, в какой том идти, и читать приходится один том, а не всю историю.

## Тома

*(строка на том: период и что в нём происходило крупного. Например: `2026-10.md`: первая обкатка, три работы владельца, первая выдача.)*

Том это отрезок времени, имя по периоду: `2026-10.md`, `2026.md`. Насколько дробить, по плотности событий: пока записей мало, один том на год; пошли выдачи и разборы, на месяц. Новый том заводится, когда старый перестаёт читаться целиком, и получает здесь свою строку.

## Зачем отдельно от истории правок

Контроль версий отвечает на «что построчно изменилось». Журнал на «какое решение приняли, почему и когда его увидел владелец». Часть решений вообще не оставляет следа в файлах: договорённости, отказы, действия в чужих кабинетах.

## Как вести

Запись появляется, когда изменилось одно из двух: **что шаблон делает для пользователя** или **причина, по которой он устроен именно так**. Правка, не задевшая ни того ни другого, записи не заслуживает, иначе журнал превратится в пересказ коммитов. Разбор поправок ([cases/](../../cases/README.md)) и выдача шаблона записываются всегда: это и есть события жизни продукта.

Дата по факту, когда изменение стало реальным для владельца или пользователя. Кратко: **что → почему → к чему ведёт.** Новое сверху тома, дата в формате `ДД.ММ.ГГГГ`.

**Поломки и инциденты отдельный жанр, и они здесь самые ценные.** У такой записи обязателен последний абзац «чему учит»: как заметили, сколько шло незамеченным и что теперь мешает повториться. Решения устаревают, уроки нет.

Закрыл задачу из [бэклога](../../backlog/README.md), здесь появляется строка о том, что получилось.

Это **не история переписки и не пересказ устройства проекта**: устройство шаблона живёт в самом шаблоне, смысл проекта в [описании](../about.md), поправки владельца и клиентов в README их работ в [cases/](../../cases/README.md).
